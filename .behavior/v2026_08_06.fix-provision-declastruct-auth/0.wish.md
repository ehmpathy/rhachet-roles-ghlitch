# wish: fix(deployer) — provision.declastruct must DECLARE its aws identity, never infer it

> dispatched from `ehmpathy/rhachet-roles-ghlitch#67`, which is the authoritative ground.
> read it in full before you start. this file carries the OUTCOME; the issue carries the EVIDENCE.

## .what

`rhx provision.declastruct` reaches aws under the identity the caller asked for, and fails loud
and early when it cannot.

two outcomes, and they ship together:

1. an `--env` run that leans on keyrack reaches aws with **that env's credentials live in the
   skill's own process**. today it does not.
2. the credential source is a **declaration by the caller**, never an inference drawn from whether
   some variable happens to be set.

## .why

both halves are live, reproduced failures — not hypotheticals.

**the first** costs an operator a wrong diagnosis every time. a `--env camp` plan failed 100% of
the time with `CredentialsProviderError: Your session has expired`, while `rhx keyrack status
--env camp` was green AND `rhx aws.whoami --env camp` returned a healthy identity. the expired
session belonged to a fallback profile the operator never chose, and the error named neither the
profile nor the account it actually tried. only a source read of the skill revealed it. that is
`rule.require.errors-name-the-fix` broken twice over: a symptom with no fix, and a cause
misattributed.

**the second is worse, because it is silent.** an operator who had deliberately selected the admin
tier had that choice discarded under them, and the apply died with `AccessDenied ...
assumed-role/AWSReservedSSO_everyday-power_.../vlad`. the error named an action and a role, and
never the fact that the skill had thrown away the identity the human picked.

## .acceptance — what proves it done

- a `--env <env>` plan that previously failed 100% now completes
- an operator who has selected an admin session **keeps it** through the run
- a run with no usable session fails **before any aws call**, with an error that names both the
  absent piece and the concrete step to fix it
- every successful run **states which identity it is about to mutate under**, so the operator can
  see it without a source read
- the live CI workflows in other repos that call today's flag still succeed for at least one release
- coverage per grain: this is a **contract**, so acceptance tests + snapshots
  (`rule.require.test-coverage-by-grain`)

## .the constraints that genuinely bind

these are not shape preferences. each one binds, and the reason is stated so you can judge edge
cases rather than obey blindly.

1. **both halves ship together, in one pr.** the issue author's argument, and i agree with it:
   half one alone makes keyrack unconditional, which turns today's variable sniff into a silent
   identity downgrade. that trades a LOUD failure for a SILENT wrong-identity apply — strictly
   worse than the defect it fixes. a partial ship is a regression.
2. **the ambient path must be ASKED FOR, never detected.** to honor a stray leftover profile would
   let a forgotten shell variable choose which aws account gets mutated. the blast radius is a
   whole account, so that path can never be reached by inference from ambient state.
3. **today's flag value survives one release as a deprecated alias.** live CI workflows across
   several repos call it; they cannot all move in the same commit.
4. the local patches in `ahbode/infrastructure` under `node_modules` are marked EPHEMERAL and are
   **not** the deliverable. they are evidence the outcome is reachable, and they die on any
   reinstall.

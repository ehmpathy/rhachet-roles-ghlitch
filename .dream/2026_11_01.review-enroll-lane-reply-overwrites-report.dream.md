# 🌙 dream: an enrolled reviewer's last reply must never stand in for its report

kind: reseed · owner: bhrain (review guard, enroll lanes) · caught 2026-11-01

## .the cue that fired

the i011 `enroll-impl-behavior-intent` given on route `v2026_08_31.guardian-infil-exfil` held no
review. the enrolled clone got a duplicate completion notice for its own sub-agent, replied "no new
content to add… 5 blockers, 6 nitpicks", and that reply became the lane's stdout. the tally parser
read "5 blockers, 6 nitpicks" from the prose and rejected the stone on 11 concerns no one can read.

## .the gap, precisely

- the enroll lane takes the clone's LAST reply as the review, not the reply that holds the report
- `contract.reviewer-output` reads counts from prose, so a reply that merely mentions counts passes
  as a verdict
- the clone transcript is lost when two clones share a cwd at spawn, so the report cannot be
  recovered after the fact

## .the shape of the fix

1. the enroll lane writes the report to a file the clone names (e.g. `$given.report.md`), and the
   guard reads that file, as the l1 lanes already do
2. a given whose body holds no `blocker.N` / `nitpick.N` section for a nonzero tally is a
   `💥 malfunction`, never a rejection
3. each enrolled clone spawns in its own worktree, so its transcript survives

## .why it is not done in this round

the defect lives in bhrain's review guard, outside this repo. this route answers the lost round via
fulcrum F18 and lets the lane re-run.

## .the gap, precisely

- **n1** — `src/domain.roles/guardian/skills/security.habitat.redteam/output.sh` is a ~360-line
  god-file bundling two grains: pure render/vibes primitives (`print_cat_header`,
  `print_tree_start/branch/item`, `print_belay`, `print_disclaimer`, `print_nested_lines`) AND
  redteam route/domain logic (`GRAIN_LIST`, `is_valid_grain`, `as_grain_hint`, `as_route_scope_token`,
  `as_normalized_scope`, `as_route_slug`, `extract_redteam_route_path`, `get_bound_route`,
  `set_route_bind`, `scaffold_route`, `set_scope_record`, `get_route_scope_field`,
  `assert_bound_route_matches_request`, `copy_route_templates`, `get_route_absent_files`,
  `compute_peer_total`, `compute_projected_cost`, `REQUIRED_ROUTE_STONES`, `print_grain_prompts`).
  sibling skills (cicd.deflake / declapract.upgrade) keep output.sh to ~8 render-only primitives.
- **n2** — `print_belay` supports only a single closing line, so security.habitat.redteam.sh
  hand-rolls ~10 near-identical 5-line belay blocks (each snapshot-pinned) instead of composing it.
- **n4** — `require_val` (main skill) and `require_init_val` (init.sh) are two divergent copies of
  one "reject an absent/flag-shaped value" guard; neither lives in the shared module.
- **n5** — the apply block's route-reuse-vs-scaffold branch is a nested two-level if/else
  (security.habitat.redteam.sh:327-379) a single route-decision communicator (returning
  `{ BOUND_ROUTE, ROUTE_STATE }`) would flatten.

- **n6** — (added from i012 r011, enroll-impl-arch-defects) `genGuardianStubBinPath` in
  `src/domain.roles/guardian/skills/.test/runGuardianSkill.ts` duplicates the shared
  `runRoleSkill.genStubBinPath` verbatim — only `STUB_BIN_SOURCE` differs. a correct fix
  parameterizes the shared helper, but that helper is consumed by ~14 test files across 5 roles, so
  the fix is a blast-radius increase into shared test infra for a nitpick — the same tradeoff already
  accepted for the output.sh split, so it folds into this same deferred pass rather than an ad-hoc
  edit mid-convergence.

none ship a behavior defect (all five graded nitpick); the tests are green.

## .the shape of the fix

one PR, done together since they touch the same files:
1. split output.sh → a render module (the `print_*` primitives) + a `route.sh` module (the grain
   enum, the route communicators/transformers, the cost transformers). every stone, init.sh, and
   the main skill re-source accordingly.
2. extend `print_belay` to accept optional pre-close `├─ fix:` / `├─ hint:` lines; collapse the ~10
   hand-rolled belays to it (re-bake their snapshots).
3. unify `require_val` + `require_init_val` into one guard in the render (or a shared) module,
   consumed by both orchestrators.
4. extract the apply route-decision into one named communicator returning `{ BOUND_ROUTE,
   ROUTE_STATE }`, flattening the nested if/else (the `scaffold_route` communicator landed at i010
   is the first step of this same pass).
5. parameterize the shared `runRoleSkill.genStubBinPath` on `STUB_BIN_SOURCE` so
   `genGuardianStubBinPath` (and the kin per-role copies) compose it rather than re-declare it — one
   coordinated pass across the ~14 test files that use it, not an ad-hoc guardian-only edit.

## .why it is not done in this round

SAFE? a render/route module split + belay/guard unification touches every belay snapshot and
re-sources across the whole skill — high blast radius for a mid-convergence round. CLEAN? no — it
ripples across output.sh, init.sh, the main skill, and ~10 snapshots, maximally churning the
`--diffs since-main` set (zero commits on branch) and re-running every l1 lane against re-shaped
files. so it fails the CLEAN test for an in-flight convergence and is deferred to a focused
post-merge PR, where the four items reshape the same surface together rather than piecemeal.

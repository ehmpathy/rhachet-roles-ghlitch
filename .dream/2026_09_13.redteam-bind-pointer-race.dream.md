# 🌙 dream: serialize the probe→bind window on concurrent inits

kind: fix · owner: guardian (habitat redteam) · caught 2026-09-13

## .the cue that fired

a peer review surfaced a concurrency hazard the hermetic stub harness could not exercise: two
concurrent `init` runs on one branch with different grains both pass the "no route bound" probe
and both bind the single-slot branch bind.

## .the gap, precisely

the loser is now LOUD: `set_route_bind` reads the bind back after `rhx route.bind.set` and halts
exit 1 with "a concurrent bind won" on a mismatch (clamp: `[case22]`). no silent wrong drive target
remains.

the residue: the window is still check-then-act. the loser scaffolds a route dir before it learns
it lost, so a human sees an orphan route dir plus the halt, and must remove the dir by hand.

## .the shape of the fix

serialize the probe→bind window with a branch-scoped lock, so the second init belays before it
scaffolds. the lock semantics depend on `rhx route.bind.set` multiplicity (overwrite, reject, or
queue), which this skill does not own.

## .why it is not done in this round

not CLEAN: the lock shape depends on a bind contract owned by the driver role. the harm is bounded
to one orphan dir behind a loud halt.

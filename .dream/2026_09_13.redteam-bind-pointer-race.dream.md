# 🌙 dream: bind-pointer race on concurrent different-grain inits

kind: fix · owner: guardian (habitat redteam) · caught 2026-09-13

## .the cue that fired

i018 l3 (r010 §2, r011 item 7) surfaced a concurrency hazard the 17 prior rounds missed, because
the hermetic stub harness cannot exercise it. graded nitpick (loud, never a silent wrong result in
the single-init common case), but it can yield a **silently wrong drive target** — the exact hazard
class this skill exists to prevent elsewhere — so it earns its own record.

## .the gap, precisely

the route-bind pointer write is check-then-act. the i011 fix made route-**dir** creation atomic
(`mkdir` without `-p`, closes the `.claims/` clobber race). but two concurrent `init` runs on one
branch with **different grains** both pass the "no route bound" probe, both create distinct route
dirs, and both call `rhx route.bind.set` against the same single-slot branch bind. the loser still
prints `bound to branch <b>` and exits 0, and a later `rhx route.drive` silently drives the OTHER
route. the same window sits on apply's re-probe: it accepts any bound route as "scaffolded + bound
a fresh route" without a check that the returned path is the one it just scaffolded.

## .the shape of the fix (two candidates)

1. **serialize the bind** — take a branch-scoped lock around the probe→bind window, so the second
   init blocks or belays instead of a silent-loser bind.
2. **post-bind path-equivalence re-check** — after `rhx route.bind.set`, read the bound route back
   and assert it equals the path just scaffolded; belay LOUD on mismatch.

both need `rhx route.bind.set`'s **multiplicity semantics** (does a second bind on one branch
overwrite, reject, or queue?), which this skill cannot assume — so the fix belongs to whoever holds
that bind contract, or follows a documented decision on it.

## .why it is not done in this round

not CLEAN: the real fix depends on a bind-multiplicity contract this skill does not own, and it is
untestable in the current hermetic harness. the stopgap holds meanwhile — the hazard is documented
and `--skip-route-bind` is the escape hatch. tracked here for the bind-contract owner.
